# 异常汇总 - 2026年6月6日

## 问题一：微信请求对话历史污染

### 问题描述

通过 OpenClaw 微信机器人发送指令时，后端会将之前的对话历史带入当前请求，导致：
- Supervisor 在分析意图时会检查之前的对话消息（包含无关的"开启在线模式"、"关闭在线模式"等历史记录）
- 意图识别可能受到历史消息干扰
- 即使当前请求处理成功，返回的结果可能被历史上下文影响

### 控制台表现

```
[Supervisor] 检查历史消息，共 7 条
[Supervisor] 检查消息 0: role=human, content=离线批次异常检测...
[Supervisor] 检查消息 1: role=ai, content=[成功] 已停止实时监控服务！...
[Supervisor] 检查消息 2: role=human, content=关闭在线模式...
[Supervisor] 检查消息 3: role=ai, content=[成功] 实时监控服务状态...
[Supervisor] 检查消息 4: role=human, content=开启在线模式...
[Supervisor] 检查消息 5: role=ai, content=[警告] 没有正在运行的实时监控服务...
[Supervisor] 检查消息 6: role=human, content=关闭在线模式...
```

### 根因分析

`/api/wechat/chat` 接口使用 `get_agent()` 获取单例 Agent 实例，该实例的 `conversation_state` 在所有请求之间共享。前端和微信共用同一个 Agent，导致对话历史互相污染。

### 解决方案

在 `/api/wechat/chat` 接口中，每次请求前重置对话状态：

```python
def run_agent():
    agent = get_agent()
    # 重置对话历史，微信每次请求都是独立的
    agent.conversation_state = {
        "messages": [],
        "pending_operation": "",
        "pending_params": {}
    }
    full_response = ""
    for chunk in agent.execute_stream(request.message, model_mode=request.model):
        if chunk:
            full_response += chunk
    return full_response
```

- `api/main.py` - `/api/wechat/chat` 接口

## 问题二：Validator 误判工具调用错误为最终失败

### 问题描述

DiagnosisAgent 执行离线批次异常检测时，工具调用过程中出现 "Connection refused" 错误（可能是 RAG 服务或 ClickHouse 短暂不可用），但最终结果是正确的。然而 Validator 检查了所有消息（包括中间工具调用消息），将 "Connection refused" 误判为最终失败，触发了 ErrorHandler 和 Fallback，返回了通用错误提示。

### 控制台表现

```
[DiagnosisAgent] 完成，新增 9 条消息
[Validator] 检测到错误 → connection_failed  (匹配: Connection refused)
[ErrorHandler] 第 1 次重试  错误类型=connection_failed
[ErrorHandler] 直接跳转 -> fallback (绕过 Supervisor)
[Fallback] 执行降级处理
```

### 根因分析

Validator 的原始逻辑检查**所有消息**（从后往前扫描最近 10 条），包括中间的工具调用消息。工具调用过程中产生的临时错误（如 "Connection refused"、"timeout"）被误判为最终失败。

### 解决方案

修改 Validator，只检查**最后一条 AI 消息**（最终结果），忽略中间工具调用消息：

```python
@staticmethod
def _validate_result(state: SupervisorState) -> dict:
    messages = state.get("messages", [])
    if not messages:
        return {"error_type": ""}

    ERROR_PATTERNS = [
        ("找不到矩阵文件",    "data_not_ready"),
        ("矩阵文件不存在",    "data_not_ready"),
        ("找不到模型文件",    "model_not_ready"),
        ("模型文件不存在",    "model_not_ready"),
        ("训练失败",          "model_not_ready"),
        ("模型缺失",          "model_not_ready"),
        ("文件缺失",          "data_not_ready"),
        ("组件不全",          "data_not_ready"),
    ]

    # 找到最后一条 AI 类型的消息
    last_ai_content = ""
    for msg in reversed(messages):
        msg_type = ""
        content = ""
        if isinstance(msg, dict):
            msg_type = msg.get("type", "")
            content = msg.get("content", "")
        else:
            msg_type = getattr(msg, "type", "")
            content = getattr(msg, "content", "") or ""

        if msg_type == "ai" and content:
            last_ai_content = str(content)
            break

    if last_ai_content:
        for pattern, err_type in ERROR_PATTERNS:
            if pattern.lower() in last_ai_content.lower():
                return {"error_type": err_type}

    return {"error_type": ""}
```

- `agent/react_agent.py` - `_validate_result` 方法

## 问题三：LLM 意图识别错误（"关闭在线模式"被误判为 OPS）

### 问题描述

用户发送"关闭在线模式"时，Supervisor 的 LLM（qwen3:8b）将其识别为 OPS 意图（运维），而不是正确的 MONITOR 意图（监控）。导致请求被路由到 OpsAgent，而 OpsAgent 没有 `stop_realtime_service` 工具，无法处理该请求。

### 控制台表现

```
[Supervisor] 意图=ops  置信度=0.80          ← 错误！应该是 MONITOR
[Router] ops → ops_agent                    ← 路由到了错误的 Agent
[OpsAgent] 处理请求: 关闭在线模式...
[OpsAgent] 记录待确认操作: unknown           ← OpsAgent 无法处理
```

### 根因分析

1. Supervisor prompt 中 MONITOR 关键词包含"在线检测"，但不包含"在线模式"
2. OPS 关键词包含"关闭"，LLM 看到"关闭"就优先匹配了 OPS
3. LLM（qwen3:8b）不够可靠，无法正确理解"关闭"+"在线模式"的组合含义

### 解决方案

在 `_supervisor_node` 中添加 Python 关键词快速分类，在 LLM 之前处理明确的意图：

```python
@staticmethod
def _fast_classify(text: str) -> str:
    """Python 关键词快速分类——在 LLM 之前执行，处理明确的意图。"""
    t = text.strip()

    # MONITOR: 开启/关闭/启动/停止 + 在线/实时/监控/模式
    monitor_patterns = [
        "开启在线", "关闭在线", "启动在线", "停止在线",
        "开启实时", "关闭实时", "启动实时", "停止实时",
        "开启监控", "关闭监控", "启动监控", "停止监控",
        "在线模式", "实时模式", "监控模式",
        "在线检测", "实时监控",
    ]
    if any(p in t for p in monitor_patterns):
        return "monitor"

    # MODEL: 切换模型、模型相关
    model_patterns = [
        "切换模型", "模型切换", "模型管理", "查看模型",
        "可用模型", "当前模型", "模型列表", "本地模型",
        "云端模型", "混合模式",
    ]
    if any(p in t for p in model_patterns):
        return "model"

    # OPS: 系统状态、配置、清理等
    ops_patterns = ["系统状态", "查看配置", "清理数据", "清理redis"]
    if any(p in t for p in ops_patterns):
        return "ops"

    # 无法快速分类，交给 LLM
    return ""
```

在 `_supervisor_node` 中调用：

```python
# Python 关键词预分类（快速、准确，避免 LLM 误判）
fast_intent = self._fast_classify(last_user_content)
if fast_intent:
    logger.info(f"[Supervisor] 关键词快速分类: {fast_intent}")
    return {"intent": fast_intent, "confidence": 1.0, "next_agent_override": ""}
```

同时更新 `prompts/supervisor_prompt.txt`，添加明确的 MONITOR 关键词规则：

```
### 第一优先级：关键词唯一匹配（必须严格遵守）
- 提到"开启在线"、"关闭在线"、"启动实时"、"停止实时"、"开启监控"、"关闭监控" → MONITOR
- 提到"在线模式"、"实时模式"、"监控模式" → MONITOR
```

### 修改文件

- `agent/react_agent.py` - 添加 `_fast_classify` 方法，修改 `_supervisor_node` 方法
- `prompts/supervisor_prompt.txt` - 更新关键词匹配规则

## 问题四：OpenClaw 返回"后端无响应"

### 问题描述

OpenClaw 微信机器人发送指令后，返回"抱歉，后端服务暂时没有响应"，但后端控制台显示请求已处理（200 OK）。

### 根因分析

1. `/api/wechat/chat` 接口没有超时处理，LLM 处理时间过长导致 OpenClaw 超时
2. `execute_stream` 是同步生成器，在 async 端口中阻塞事件循环
3. 意图识别错误导致请求被路由到无法处理的 Agent，返回了无意义的回复

### 解决方案

在 `/api/wechat/chat` 接口中添加超时处理和异步执行：

```python
import asyncio

WECHAT_TIMEOUT = 60  # 60秒超时

def run_agent():
    agent = get_agent()
    agent.conversation_state = {
        "messages": [],
        "pending_operation": "",
        "pending_params": {}
    }
    full_response = ""
    for chunk in agent.execute_stream(request.message, model_mode=request.model):
        if chunk:
            full_response += chunk
    return full_response

try:
    loop = asyncio.get_event_loop()
    full_response = await asyncio.wait_for(
        loop.run_in_executor(None, run_agent),
        timeout=WECHAT_TIMEOUT
    )
    if not full_response:
        return {"content": "抱歉，处理失败，请稍后重试。"}
    return {"content": full_response.strip()}
except asyncio.TimeoutError:
    return {"content": "抱歉，处理超时（超过60秒），请稍后重试或简化您的问题。"}
except Exception as e:
    return {"content": f"抱歉，处理出错: {str(e)}"}
```

  ↓

  ↓
DiagnosisAgent: 调用工具执行检测（工具调用过程中可能有临时错误）
