# 三链分开模型：OpenClaw 云端 + 后端混合模型方案

## 架构总览

```
微信 → OpenClaw（WSL，云端 Qwen 3.7 Max）→ 后端 FastAPI（Windows）
                                                    │
                                           LangGraph Supervisor
                                                    │
                              ┌─────────────────────┼─────────────────────┐
                              ↓                     ↓                     ↓
                         简单任务                监控任务              复杂任务
                     Ollama qwen3:8b           纯 Python           云端 qwen3.6-plus
                      （本地 8B）             （零 LLM 延迟）        （云端大模型）
                              │                     │                     │
                         Supervisor              Monitor              Diagnosis
                         General                                       Data / Ops
```

---

## 一、OpenClaw 为什么只用云端模型

### 原因

OpenClaw Agent 框架为云端大模型设计，依赖以下能力：

| 能力 | 云端大模型（Qwen Max） | 本地 8B 模型（qwen3:8b） |
|------|:---:|:---:|
| 长系统提示词理解（AGENTS.md ~3000 字） | ✅ | ❌ 超时 |
| OpenAI function calling 协议 | ✅ | ❌ 工具调用冲突 |
| 多轮推理 + 工具选择 | ✅ | ❌ 返回文本而非工具调用 |
| 思考模式兼容 | ✅ | ❌ reasoning tokens 导致响应不完整 |

### 结论

OpenClaw 保持使用 `qwen/qwen3.7-max-preview`（云端），配置在 `openclaw.json` 中：

```json
"agents": {
  "defaults": {
    "model": {
      "primary": "qwen/qwen3.7-max-preview"
    }
  }
}
```

## 二、后端混合模型实现

### 设计思路

后端 LangGraph Supervisor 系统有 5 个子 Agent，按任务复杂度分配模型：

| 子 Agent | 任务类型 | 模型 | 理由 |
|----------|:---:|:---:|------|
| **Supervisor** | 意图分类（6 选 1） | Ollama qwen3:8b | 简单分类任务，8B 足够 |
| **General** | 时间、计算、闲聊 | Ollama qwen3:8b | 简单问答，无需强推理 |
| **Monitor** | 实时监控启停/查询 | 纯 Python | 关键词匹配，零 LLM 延迟 |
| **Diagnosis** | 异常检测、RAG 检索 | 云端 qwen3.6-plus | 需要强推理 + 长上下文 |
| **Data** | 数据预处理、批次管理 | 云端 qwen3.6-plus | 复杂数据操作 |
| **Ops** | 系统状态、重启、删除 | 云端 qwen3.6-plus | 高风险操作，需要强判断力 |

### 代码改动

#### 1. `model/factory.py` — 导出双模型

```python
from langchain_ollama import ChatOllama
from langchain_community.chat_models import ChatTongyi

def _build_ollama_model() -> BaseChatModel:
    """本地 Ollama（简单任务）"""
    return ChatOllama(
        model=llm_config["ollama"]["models"]["default"],  # qwen3:8b
        base_url=llm_config["ollama"]["base_url"],         # http://localhost:11434
        temperature=0.7,
        num_predict=1024,
    )

def _build_cloud_model() -> BaseChatModel:
    """云端 Qwen（复杂任务）"""
    return ChatTongyi(model=rag_config["vector_store"]["chat_model"])  # qwen3.6-plus

chat_models = _build_cloud_model()   # 云端
ollama_model = _build_ollama_model() # 本地
```

#### 2. `agent/react_agent.py` — 分配模型

```python
from model.factory import chat_models, ollama_model

# Supervisor 使用本地模型
response = ollama_model.invoke([
    SystemMessage(content=load_supervisor_prompt()),
    HumanMessage(content=last_user_content),
])

# General Agent 使用本地模型
self.general_agent = create_agent(model=ollama_model, ...)

# Diagnosis / Data / Ops 使用云端模型
self.diagnosis_agent = create_agent(model=chat_models, ...)
self.data_agent = create_agent(model=chat_models, ...)
self.ops_agent = create_agent(model=chat_models, ...)
```

#### 3. 消息过滤函数 `_clean_messages_for_cloud()`

由于 Ollama 和云端模型的消息格式不兼容（tool 消息格式差异），新增过滤函数：

```python
def _clean_messages_for_cloud(messages: list) -> list:
    """过滤消息，移除 tool 消息和 tool_calls，适配 DashScope API"""
    cleaned = []
    for msg in messages:
        role = ...  # 提取 role
        content = ...  # 提取 content
        if role == "tool":      # 跳过 tool 消息
            continue
        if role in ("ai", "assistant") and not content:  # 跳过空 ai 消息
            continue
        # 只保留 human 和 ai 消息
        ...
    return cleaned
```

在 Diagnosis / Data / Ops Agent 调用前，统一过滤：

```python
clean_msgs = _clean_messages_for_cloud(state["messages"])
result = agent.invoke({"messages": clean_msgs})
```

#### 4. 配置文件

**`config/llm.yml`**（本地 Ollama）：
```yaml
default_provider: "ollama"
ollama:
  base_url: "http://localhost:11434"
  models:
    default: "qwen3:8b"
```

**`config/rag.yml`**（云端模型）：
```yaml
vector_store:
  chat_model: "qwen3.6-plus-2026-04-02"
```

## 三、遇到的问题及解决方案

### 问题 1：OpenClaw + 本地模型 — `incomplete terminal response`

**现象**：OpenClaw 使用 `ollama/qwen3:8b` 时，返回 `ollama/qwen3:8b ended with an incomplete terminal response`

**原因**：`qwen3:8b` 是思考模型（thinking model），会先输出大量 reasoning tokens，OpenClaw 认为响应不完整

**尝试的解决方案**：
- 在 `openclaw.json` 中设置 `reasoning: false` → 无效，模型仍然输出 reasoning
- 在 AGENTS.md 中加 `/no_think` → 简单查询可以，但模型不再使用 exec 工具

**最终方案**：放弃 OpenClaw 使用本地模型，OpenClaw 保持云端 Qwen

---

### 问题 2：OpenClaw + 本地模型 — `client tool name conflict: exec`

**现象**：`qwen3:8b` 尝试调用 exec 工具时报 `client tool name conflict: exec`

**原因**：模型生成的工具调用名称与 OpenClaw 内置的 `exec` 工具名冲突

**结论**：8B 模型无法正确遵循 OpenClaw 的工具调用协议

---

### 问题 3：OpenClaw + 本地模型 — AGENTS.md 太长导致超时

**现象**：OpenClaw 调用 Ollama 超时，日志显示 `LLM request timed out`

**原因**：AGENTS.md 包含大量默认模板（心跳、群聊、记忆管理等），系统提示词过长，8B 模型处理太慢

**尝试的解决方案**：
- 精简 AGENTS.md（移除默认模板）→ 减少了 token 数，但仍超时
- 增加 OpenClaw 超时配置 → `timeout` 字段不在 provider schema 中，配置无效

**最终方案**：同上，OpenClaw 保持云端

---

### 问题 4：后端云端模型 — `Model not exist`

**现象**：Ops Agent 执行失败，返回 `Model not exist`

**原因**：`rag.yml` 中 `chat_model` 设为 `qwen3:8b`（Ollama 模型名），但 `ChatTongyi`（DashScope API）不识别此模型名

**解决方案**：将 `rag.yml` 改回云端模型名 `qwen3.6-plus`

---

### 问题 5：后端混合模式 — `messages with role "tool" must be a response to a preceeding message with "tool_calls"`

**现象**：Ops Agent 调用云端 DashScope API 时报 tool 消息格式错误

**原因**：对话历史中包含 Ollama 产生的 tool 消息（General Agent 使用 Ollama），DashScope API 要求 tool 消息必须紧跟 tool_calls 消息，格式不兼容

**解决方案**：新增 `_clean_messages_for_cloud()` 函数，在调用云端模型前过滤掉 tool 消息和空 ai 消息

---

### 问题 6：后端云端模型 — `url error, please check url`

**现象**：Data Agent 执行失败，返回 URL 错误

**原因**：`rag.yml` 中模型名 `qwen3.6-plus-2026-04-02` 不存在，DashScope API 根据模型名构造 URL，无效模型名导致 URL 错误

**解决方案**：使用正确的模型名（如 `qwen3.6-plus`，不带日期后缀）

## 四、性能对比

| 场景 | 改动前（全云端） | 改动后（混合） |
|------|:---:|:---:|
| Supervisor 意图分类 | ~5.5s（云端） | ~3s（本地 Ollama） |
| General 简单问答 | ~10s（云端） | ~8s（本地 Ollama） |
| Monitor 监控操作 | ~2s（纯 Python） | ~2s（纯 Python） |
| Ops 复杂运维 | ~10s（云端） | ~10s（云端） |
| API 费用 | 每次调用计费 | 仅复杂任务计费 |
